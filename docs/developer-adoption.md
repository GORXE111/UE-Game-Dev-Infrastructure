# 独立开发者接入路线

基础设施仓库维护可执行工具、示例和测试。展示仓库维护架构介绍、接入入口和已经验证的范围。用全新检出、团队自己的 UE 安装和空白项目复验每个里程碑。用户可以先接入配置表或测试工具，再逐步接入发布链路。

| 顺序 | 交付 | 外部开发者验收 |
| --- | --- | --- |
| 1 | 脚手架、独立打表、Jenkins 本机门禁 | 一条命令生成空白 C++ 工程、导出可导入 UE 的配置并执行签名事务测试。开发机和 Jenkins 走同一入口，报告可单独存档 |
| 2 | 项目接入配置、资源和启动门禁 | 项目声明 UE 路径、Targets、资产入口和发布身份。编辑器检查资产登记、类和加载。Cook 后根据实际包清单检查依赖、软引用和大小，启动样板核对表及关键地图 |
| 3 | 客户端与专用服务器构建、启动和测试 | 在自备构建节点产出 Win64、Android 和项目所需的服务器包。用项目配置启动和停止服务器，记录版本、日志及就绪状态。联机测试覆盖客户端连入、兼容性和更新后重连 |
| 4 | 签名发布、私有暂存和公网读回 | Jenkins 将同一份已测试的构建交给独立签名和发布任务。测试环境验证域名、TLS、缓存、整包摘要及失败回退。通过公网读回和审批后切换活动版本 |
| 5 | 独立复现与维护 | 由外部团队在干净节点按文档走完流程。公开每个平台实际通过的环境、已知限制和版本支持周期。确认工具许可、第三方依赖及 UE 授权范围 |

## 本轮可用入口

- [配置表、资源检查和 Jenkins](config-and-ci.md) 从 CSV 和版本化 schema 生成 JSON 与摘要。样例包含一个可直接导入 UE 的 Gameplay Tags 表和一个玩法参数表。
- [脚手架](../Tools/Scaffold/README.md) 生成独立 C++ 工程、Runtime 插件或 Editor 插件。
- [现有发行与网关工具](packaging-and-publication.md) 提供签名清单、兼容检查、包体和发布参考。实际项目的 Build、Cook、健康回执和存档策略由项目适配器提供。[服务器网关](server-gateway.md)

优先统一构建节点与游戏项目之间的输入输出。让同一项目配置指定客户端和专用服务器 Target、平台、地图与资源清单。让每个阶段输出可归档的版本和摘要，便于用同一产物重跑测试、签发和回退。版本标识贯穿配置生成、Cook、测试、签名和公网读回。

配置表下一步加入跨表引用、业务约束和客户端／服务器字段范围。当前样板的 JSON 可以作为服务端输入契约的起点，服务端启动时实际加载、验证和报告表版本需要单独接入。私有 Luban 集成可作为后续可选适配器，先确认所需组件及其分发许可。

Jenkins 负责调度。UE 编译和无头测试放在有相应引擎与 SDK 的节点，签名与线上推广分开授权。游戏专用服务器和提供补丁下载的 HTTPS 网关分别维护各自的启动、健康与回退流程。 [Jenkins Pipeline](https://www.jenkins.io/doc/book/pipeline/) · [Jenkins 凭据](https://www.jenkins.io/doc/book/using/using-credentials/)
